# Deployment Guide — Sehatkita Frontend

## Prerequisites

- Node.js 20+
- npm 10+
- GitHub account (untuk CI/CD)
- Deployment target (Vercel, Railway, Netlify, atau custom server)

## Environment Setup

### Development
```bash
cp frontend/.env.example frontend/.env.local
# Edit .env.local dengan nilai development
```

### Production
```bash
cp frontend/.env.example frontend/.env.production.local
# Edit .env.production.local dengan nilai production
export NEXT_PUBLIC_API_BASE_URL=https://api.sehatkita.id/api/v1
export NEXT_PUBLIC_ENABLE_ANALYTICS=true
```

## CI/CD Pipeline

### GitHub Actions Workflow (`.github/workflows/frontend-ci-cd.yml`)

Trigger: Push ke `main` atau `develop`, Pull Request

**Stages:**
1. **Lint** — ESLint check
2. **Test** — Jest unit tests + coverage
3. **Build** — Next.js production build
4. **Deploy** — Push ke production (hanya dari `main`)

## Deployment Options

### Option 1: Vercel (Recommended)
Easiest untuk Next.js. Auto-deploy dari GitHub.

1. Login ke [vercel.com](https://vercel.com)
2. Import `sehatkita` repo
3. Set Environment Variables
4. Deploy
5. Auto-redeploy on push to `main`

```bash
# Or via CLI
npm i -g vercel
cd frontend
vercel --prod
```

### Option 2: Railway
Flexible, support custom node/docker.

1. Login ke [railway.app](https://railway.app)
2. Create new project from GitHub
3. Configure build: `npm run build`
4. Configure start: `npm start`
5. Add environment variables
6. Deploy

### Option 3: Netlify
Simpler static hosting (jika tidak perlu API runtime).

1. Login ke [netlify.com](https://netlify.com)
2. Connect GitHub repo
3. Build command: `npm run build`
4. Publish directory: `.next`
5. Deploy

### Option 4: Custom Server
Full control, self-hosted.

```bash
# Build
npm run build

# Copy to server
scp -r .next/ user@server:/app/frontend/

# SSH to server
ssh user@server

# Install dependencies & start
cd /app/frontend
npm install --production
npm start
```

## Post-Deployment

### Health Check
```bash
curl https://frontend.sehatkita.id
# Should return 200 OK with landing page
```

### Monitoring
- Error tracking: Sentry (optional)
- Analytics: PostHog (optional)
- Performance: Lighthouse CI

### Rollback
```bash
# Vercel: revert to previous deployment from dashboard
# Railway: select previous build from deployment history
# Manual: redeploy previous git commit
git checkout <commit-hash>
git push -f origin main  # Force push (use carefully!)
```

## Performance Targets

- **LCP** (Largest Contentful Paint): < 2.5s
- **FID** (First Input Delay): < 100ms
- **CLS** (Cumulative Layout Shift): < 0.1
- **Build size**: < 500KB (gzipped)
- **Time to Interactive**: < 3.5s

## Security Checklist

## Troubleshooting

### Build fails
```bash
npm ci  # Clean install
npm run build
```

### 404 on nested routes
Next.js App Router issue — ensure middleware.ts & next.config.js correct.

### API 502 errors
Check backend API health & CORS headers.

### Slow performance
- Check build size: `npm run build --analyze`
- Enable image optimization
- Reduce bundle: tree-shaking, code splitting
